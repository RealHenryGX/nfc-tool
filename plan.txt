## 1. Package Selection & Why

### NFC
- **`nfc_manager`** – high‑level Android/iOS wrapper that handles the system NFC dialog, NDEF parsing, and writing. Perfect for reading/writing standard NDEF records without low‑level byte manipulation.  
  *Use for*: reading/writing Text, URI, WiFi, vCard, SMS, etc. It also exposes the tag’s tech list and UID in some scenarios (though UID is often missing on modern Android due to privacy restrictions).  
- **`flutter_nfc_kit`** – lower‑level access that gives you raw `transceive` commands, full tech list, and UID (when the OS allows).  
  *Use for*: reading raw bytes, interacting with non‑NDEF tags (Mifare Classic, Ultralight EV1 memory dumps), or if you need absolute control over the tag.  

**My recommendation**: Start with `nfc_manager` for 90% of your features. It’s simpler, battle‑tested, and handles the lifecycle automatically. If you later need raw transceive (e.g., to read a Mifare sector), add `flutter_nfc_kit` only for those edge cases—they can coexist.

### QR / Barcode
- **`mobile_scanner`** – lightweight, fast, and embeds the camera view natively. Supports QR and many barcode formats.  
- **`google_mlkit_barcode_scanning`** – Google’s ML Kit solution, very accurate but adds significant APK size (bundled model).  

**Recommendation**: `mobile_scanner` is sufficient for QR parsing and content type detection. It doesn’t run ML models, so you just parse the string afterwards.

### Local Storage
- **`Hive`** – fast, NoSQL, great for small JSON‑like templates. Supports lazy loading and encryption.  
- **`Isar`** – also fast, with richer queries, but has a slightly steeper setup.  

**Recommendation**: **Hive** is perfect because your templates are small JSON blobs. Use a single box for templates, one for history. Add `hive_flutter` for Flutter‑specific initialisation.

### State Management & Navigation
- **`Riverpod`** – highly testable, composes easily, and can scope providers to features.  
- **`go_router`** – for declarative routing with deep links (useful if you want to share a template via QR link later).  

**Add also**: `permission_handler` for runtime permissions, `intl` for date formatting in history, `share_plus` for sharing JSON/files.

## 2. Core Data Models

Stick to simple, immutable classes that can be serialised to/from Hive. Example:

```dart
// tag_template.dart
import 'ndef_record.dart';

@HiveType(typeId: 0)
class TagTemplate extends HiveObject {
  @HiveField(0)
  final String id; // uuid
  @HiveField(1)
  String name;
  @HiveField(2)
  List<NDEFRecord> records;
  @HiveField(3)
  DateTime createdAt;
  // ...
}
```

For `NDEFRecord`, model each type:

```dart
@HiveType(typeId: 1)
class NDEFRecord extends HiveObject {
  @HiveField(0)
  String type; // 'text', 'uri', 'wifi', 'vcard', etc.
  @HiveField(1)
  Map<String, dynamic> payload; // { 'ssid': '...', 'password': '...' }
}
```

Keep payload as a map so you can add arbitrary fields without changing the model.

## 3. Service Layer Design

Encapsulate all business logic in services that depend on plugins. This makes testing possible with mock implementations.

```dart
class NfcService {
  Future<TagInfo?> readTag();
  Future<void> writeTag(List<NDEFRecord> records);
  Future<bool> isNfcAvailable();
  Stream<NfcEvent> get onTagDiscovered; // for batch mode
}
```

Implementation using `nfc_manager`:

- **Read**: start session, wait for `NfcManager.instance.startSession(onDiscovered: (tag) {...})`. Parse NDEF records from `tag.ndef.records`. Tech list & UID come from `tag.data`.
- **Write**: build a `NdefMessage` from your `NDEFRecord` list, then `tag.ndef.write(...)`.

For batch writing, keep the session alive, write, and then prompt the user to tap the next tag without stopping the session. You’ll need to call `NfcManager.instance.stopSession()` only after the batch is complete or cancelled.

## 4. Building the NDEF Record Factory

You need a utility that converts your `NDEFRecord` (with type + payload map) into the appropriate NDEF record for the platform.  
Example snippet for WiFi:

```dart
NdefRecord buildWifiRecord(Map<String, dynamic> payload) {
  final ssid = payload['ssid'];
  final password = payload['password'];
  final encryption = payload['encryption'] ?? 'WPA'; // WPA, WEP, nopass
  final wifiString = 'T:$encryption;S:$ssid;P:$password;;';
  return NdefRecord(
    typeNameFormat: NdefTypeNameFormat.mimeMedia,
    type: 'application/vnd.wfa.wsc',
    payload: Uint8List.fromList(wifiString.codeUnits),
  );
}
```

Create a factory for every supported type (vCard is a long string format—use a helper to generate it). Store the mapping in a single `NdefBuilder` class.

## 5. QR → NFC Wizard

The flow is straightforward:

1. **Scan** with `mobile_scanner` → get raw string `“https://example.com”`.
2. **Detect type** using regex or utility functions (URL, email, phone, SMS, WiFi, geo, vCard).  
   - WiFi: match `WIFI:S:...;T:...;P:...;;`
   - vCard: starts with `BEGIN:VCARD`
   - etc.
3. **Construct** an `NDEFRecord` automatically.
4. **Preview** screen shows the detected type and let the user edit fields.
5. **Write** to tag using `NfcService.writeTag([record])`.

Save the result as a template with one tap.

## 6. Batch Writing Implementation

Pseudo‑code:

```dart
Future<void> startBatchWrite(List<NDEFRecord> records) async {
  await NfcManager.instance.startSession(
    onDiscovered: (tag) async {
      try {
        final ndef = Ndef.from(tag);
        await ndef?.write(buildNdefMessage(records));
        showSuccessDialog();
        // Keep session alive for next tag
      } catch (e) {
        showErrorDialog();
        // Optionally stop session
      }
    },
    pollingMode: NfcPollingMode.all,
    alertMessage: 'Hold device near a tag',
  );
}
```

**Important**: Android’s NFC system dialog has a timeout. You’ll need to call `NfcManager.instance.stopSession()` and restart it after each successful write to prevent the OS from closing it. A better pattern: use `stopSession()` after writing, then immediately call `startSession()` again for the next tag. This gives a fresh “tap to write” prompt.

## 7. Tag History & Export

Each read/write operation stores:

```dart
@HiveType(typeId: 2)
class HistoryEntry {
  @HiveField(0)
  String uid;
  @HiveField(1)
  DateTime timestamp;
  @HiveField(2)
  String action; // 'read', 'write', 'batch'
  @HiveField(3)
  String content; // JSON of records
  @HiveField(4)
  bool success;
}
```

Export to CSV using `csv` package. Use `path_provider` to get a temporary directory, then `share_plus` to share the file.

## 8. Raw Data & Advanced Writer

For raw hex view, you’ll need `flutter_nfc_kit`. Use `transceive` commands to read memory blocks (especially for Mifare Ultralight & Classic).  
- For NDEF tags, the raw bytes of an `NdefMessage` are available and can be displayed.  
- **Lock tag**: Send the appropriate command via `transceive` (e.g., set CC byte or OTP on Ultralight). This is tag‑specific, so provide warnings.

The app can offer an “Advanced” tab with a hex viewer/editor for raw bytes (import/export binary/JSON).

---

## 9. Sharing Templates & Backup

- **Share as QR**: encode the whole template (records array) as a JSON string into a QR code. Use `qr_flutter` to display it.  
- **Share as JSON file**: use `share_plus` to send `template.json`.  
- **Backup/Restore**: read all templates from Hive, write to a JSON file, share or save to downloads. Restore by picking a file with `file_picker` and merging.

## 11. Permissions & Android 15+ Handling

- **`NFC`** permission is declared in `AndroidManifest.xml`. It’s a “normal” permission, but you must also add the `<uses-feature android:name="android.hardware.nfc" android:required="false" />` to allow devices without NFC.  
- **Camera** for QR scanning – needs runtime `permission_handler`.  
- Android 15 introduces restrictions on foreground services. As long as your NFC operations happen when the app is in the foreground (which is the case when the NFC dialog is visible), you’re fine. No foreground service needed.

## 13. Testing and Debugging

- Use a physical Android device with NFC—**emulators do not support NFC**.  
- For QR, the emulator camera can point to a virtual scene, but test on real device.  
- Unit test your NDEF builder and content detectors thoroughly; they’re pure Dart logic.  
- You can mock `NfcManager` using a custom stub that returns predefined `NfcTag` data.

---

## 14. Final Thoughts

Your project structure is already clean and scalable. Stick to it. Use Riverpod with `StateNotifier` or `AsyncNotifier` for each feature, and keep the UI dumb.  
The hardest part will be managing the NFC session lifecycle reliably (Android manufacturers behave differently). `nfc_manager` abstracts most of this, but batch mode will need careful handling of start/stop.

If you follow this roadmap, you’ll end up with a tool that genuinely rivals—and in some areas surpasses—NFC Tools, with the added benefit of being open‑source and extendable.
